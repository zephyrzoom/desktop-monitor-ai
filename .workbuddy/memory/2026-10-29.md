# 2026-10-29

## 修复日报时间段时区偏差（UTC → 本地）

- 现象：日报「工作内容」里的时间段比实际作息早 8 小时。
- 根因：`screenshots` / `active_windows` 的 `timestamp` 默认值取
  `strftime('%Y-%m-%dT%H:%M:%f','now')`，SQLite 里这是 **UTC**；而
  `analyzer::hhmm()` 直接截字符串时分喂给模型和页面，没有换算本地时间。
  佐证：同一条记录 `timestamp=2026-06-04T08:38:41`，文件名是 `16-38-41`
  （本地），`strftime('%H:%M', timestamp, 'localtime')` = 16:38。
- 修改（一律「写入保持 UTC，读取统一转本地」，避免新旧数据混口径）：
  - `src-tauri/src/analyzer/mod.rs`：新增 `parse_db_timestamp()`（先试 RFC3339，
    再试 4 种 naive 格式，按 UTC 解释后转 `Local`），`hhmm()` 改用它。
  - `src-tauri/src/db/queries.rs`：所有 `date(timestamp)` → `date(timestamp,'localtime')`；
    `window_switch_sequence` 的 `substr(timestamp,12,5)` → `strftime('%H:%M', timestamp,'localtime')`；
    task_memory 的 `date('now',...)` 补 `'localtime'`。这同时修正了「本地 00:00-08:00
    的记录被归到前一天」的日期分桶错误。
  - 前端：新增 `src/renderer/src/lib/date.ts` 的 `localDateString()`，替换
    `new Date().toISOString().split('T')[0]`（Today.tsx、DailyReport.tsx 默认日期）。
  - `monitors/screenshot.rs`：截图目录改用本地日期（与 DB 口径一致）；
    cleanup 里 `remove_dir_all` → `remove_dir`（只删空目录），避免凌晨时段
    目录名（UTC）比 cutoff（本地）早一天而误删未过期截图。
- 验证：`npm run typecheck` 通过、`cargo check` 通过。
- 注意：**已生成的日报 `result_json` 里 time_range 仍是错的**，需要对该日期点
  「重新分析」才会重算（「补偿分析」只补缺失日期，不会重跑已有日报）。
