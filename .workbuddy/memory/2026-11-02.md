## CI：新分支不触发构建（同日）

- 现象：`new-ui` 分支 push 后 GitHub Actions 无任何运行记录。
- 原因：`.github/workflows/build.yml` 的 `on.push.branches` 只列了 `main/master/tauri`，
  新分支不在白名单里；`pull_request` 也只监听 main/master（这是 base 分支）。
- 修复：push 分支补 `new-ui`，pull_request 分支补 `tauri/new-ui`。
- 排查手法：无 gh CLI 时用公开 API 看运行记录
  `curl -s https://api.github.com/repos/<owner>/<repo>/actions/runs?per_page=5`
  （返回体可能含控制字符，Python 解析要 `json.loads(s, strict=False)`）。
- `release-nightly` / `release` 的 `if` 仍只覆盖 main/master 与 tag，改版分支只构建不发布。

- 坑：`magick` 自带 SVG 渲染器不认 `gradientUnits`，渐变会整块丢失；预览请用

## 日报：合并补算/重算按钮 + 日历标记（同日）

- 结论先行：原「补偿分析」(`backfill_all`) 与「重算 7 天」(`reanalyze_recent`) 只在
  「今天前 6 天内缺日报的日期」上重叠，其余集合不同（前者全历史只补缺、含今天；后者只 6 天、
  覆盖已有、排除今天），同时点会白跑一轮 LLM。
- 后端合并为 `analyzer::rerun_daily(rt, days: Option<i64>) -> RerunOutcome`：
  - 范围内「有截图」的日期全部处理，缺失靠 `analyze_daily` 的 upsert 补上，已有的覆盖重写；
  - `retain(|d| d < today)` 永远排除今天；`days=Some(n)` 取 `today-n .. yesterday`（正好 n 天）；
  - 返回 `total / succeeded / filled`（filled 用 `all_daily_analysis()` 差集算，用于提示语）。
  - 命令层 `analysis_backfill` + `analysis_reanalyze_recent` → 单个 `analysis_rerun(days)`，
    前端 `api.rerunAnalysis(days | null)`。定时任务的 `backfill_range`（近 30 天补缺）保持不变。
- 前端：`AnalysisContext` 的 `backfilling` / `reanalyzing` 合并为 `rerunning` +
  `triggerRerun`；`DailyReport` 右上角单按钮 `批量补算` + `.menu` 下拉（7 天 / 30 天 / 全部历史），
  完成后 Alert 显示「共 N 天（补算 x 天，重写 y 天），成功 z 天」。
- 日历：`components/DatePicker.tsx` 由原生 `input[type=date]` 改为自定义弹层日历
  （周一起始、上/下月切换、回到今天、Esc/点外部关闭），`markedDates` 命中的日期下方打 4px 圆点；
  连带删掉 `globals.css` 里隐藏原生日历按钮的三条 `input[type='date']` 规则。
  `Icon.tsx` 新增 `chevron-left`。
- 视觉验证方式（可复用）：临时 `src/renderer/__preview.html` + `src/__preview.tsx` 挂单个组件，
  `npx vite` 起服务后用
  `"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" --headless=new --no-sandbox
  --user-data-dir=/tmp/edge-profile --screenshot=/tmp/x.png <url>` 截图，验证后删临时文件。
  直接访问 `/#/daily` 也能渲染真实页面（Tauri invoke 全部 reject，但被 try/catch 吃掉）。

## 季度/年度汇总：定时任务自动生成（同日）

- 背景：此前 `Scheduler` 只跑日报（`analyze_daily` + `backfill_range`），季度/年度汇总
  只有手动按钮（`summary_trigger`）一条路径，`AnalysisConfig` 也没有对应调度开关。
- 后端 `analyzer/mod.rs`：
  - 新增 `last_finished_quarter(today) -> (年, 季度)`：`month0()/3` 得当前季度索引，
    `(idx+3)%4` 得上一季度，`idx==0` 时年份减一（1 月 1 日 → 上一年 Q4）。
  - 新增 `generate_finished_periods(rt)`：依次看季度、年度；先 `has_periodic_summary`
    查 `periodic_summary` 表，已有或该周期无日报（`generate_periodic` 返回 `Ok(false)`）就跳过，
    所以每天跑也只调一次模型；季末/年末没开机时下次定时任务自动补上。
  - `run_scheduled` 在 `backfill_range` 之后调用它，仍在 `try_begin_analysis` 锁内。
  - 生成成功 `rt.emit("summary:result", label)`；测试模块覆盖 7 个季度边界日期。
- 配置：`AnalysisConfig` 加 `auto_quarterly` / `auto_yearly`，默认 `true`；
  前端 `Settings.tsx` 的「AI 分析」卡片新增「自动汇总」分组（两个 switch-row），
  `updateAnalysis` 允许 boolean。`globals.css` 加 `.switch-row + .switch-row` 间距。
- 顺手修：`summary_trigger` 原先没有 `try_begin_analysis` 互斥，会和日报分析并发发 LLM 请求；
  现在忙时返回 `status: "busy"`。
- 前端事件：`api.onSummaryGenerated` → `summary:result`，`AnalysisContext` 收到后
  `notifyComplete()`，汇总页自动重新拉取。
- 校验：`npm run typecheck` / `cargo check` / `cargo test --lib` 全绿；
  `eslint` 改动前后同为 9 个既有 `react-hooks` 报错（`git stash` 对比确认无新增）。
