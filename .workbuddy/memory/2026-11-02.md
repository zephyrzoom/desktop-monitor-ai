## CI：新分支不触发构建（同日）

- 现象：`new-ui` 分支 push 后 GitHub Actions 无任何运行记录。
- 原因：`.github/workflows/build.yml` 的 `on.push.branches` 只列了 `main/master/tauri`，
  新分支不在白名单里；`pull_request` 也只监听 main/master（这是 base 分支）。
- 修复：push 分支补 `new-ui`，pull_request 分支补 `tauri/new-ui`。
- 排查手法：无 gh CLI 时用公开 API 看运行记录
  `curl -s https://api.github.com/repos/<owner>/<repo>/actions/runs?per_page=5`
  （返回体可能含控制字符，Python 解析要 `json.loads(s, strict=False)`）。
- `release-nightly` / `release` 的 `if` 仍只覆盖 main/master 与 tag，改版分支只构建不发布。

## 应用图标换新（同日）

- 旧图标是 Electron 时代产物（`#1a1a2e` 深蓝圆底 + 显示器线稿），与新 UI 完全不搭。
- 母版统一为 `resources/icon.svg`（1024 画布 / 824 主体 / 圆角 185 的 macOS 规范留白），
  蓝紫渐变 `#5570FF → #6C5CF5 → #8B5CF6` + 白色 `activity` 曲线（stroke 2.5，
  scale 21），保证 16–32px 下仍可辨认。
- 生成方式：`npx tauri icon resources/icon.svg`，一次产出 `icon.icns` / `icon.ico`
  （16/24/32/48/64/256）/ `32x32` `128x128` `128x128@2x` `icon.png` 与 Windows 磁贴系列；
  会顺带生成 `android/`、`ios/` 目录，桌面项目可直接删掉。
- `tauri icon` 生成的 `tray.png` 不会更新，需手动用 `32x32.png` 覆盖（当前无托盘代码）。
- 坑：`magick` 自带 SVG 渲染器不认 `gradientUnits`，渐变会整块丢失；预览请用
  `/Applications/Inkscape.app/Contents/MacOS/inkscape --export-type=png --export-width=1024`。
- 图标只在**打包**后生效：macOS `tauri dev` 的 Dock 图标是可执行文件的通用图标，
  Windows dev 会因为 tauri-build 嵌入 ico 而直接生效。
- 同时把 `tauri.conf.json` 的 `backgroundColor` 从 `#0f1115` 改为 `#f6f7f9`。

## Windows 构建改为只出便携版（同日）

- Tauri 2 没有 `portable` 这个 bundle target（`--bundles` 只有 nsis/msi/app/dmg/deb 等），
  「便携版」本质就是不打包、只编出裸 exe，所以统一走 `tauri build --no-bundle`。
- `package.json` `build:win` → `npm run bump && tauri build --no-bundle`。
- `tauri.conf.json` `bundle.targets` 由 `["nsis","deb"]` 改为 `["deb"]`（targets 按当前平台过滤，
  macOS 上 deb 直接忽略）。`bundle.windows.nsis` 配置块保留，方便以后临时 `--bundles nsis`。
- CI `build-windows`：`npx tauri build --no-bundle`，产物只拷
  `target\release\desktop-monitor.exe` → `dist\desktop-monitor-portable.exe`，
  删掉原来拷 `bundle\nsis\*.exe` 那行。
- 便携 exe 依赖系统自带 WebView2（Win10 1803+ 内置），发布说明保留该提示。
