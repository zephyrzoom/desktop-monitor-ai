## feat: 配置页模型支持下拉选择可用模型

- 需求：填完 API Key / Base URL 后，模型可以从接口返回的可用模型里下拉选择。
- 后端：`analyzer/llm.rs` 抽出 `request_headers()` 供 chat 与新增的 `list_models()` 共用；
  请求 `GET {baseUrl}/models`（15s 超时），归一化误填的 `/chat/completions`、`/models` 后缀；
  兼容 `data` / `models` 数组、元素 `id`/`name`/`model`、字符串数组，去重排序；
  401/403/404/429 返回可直接展示的中文原因。新增命令 `analysis_list_models`
  （参数缺省时回退到已保存配置），已在 lib.rs 的 invoke_handler 注册。
- 前端：`api.ts` 加 `listModels(query)`；Settings 在表单参数变化后 800ms 防抖自动拉取
  （传当前未保存的表单值），模型字段改为 select + 刷新按钮 + 手动输入切换；
  当前模型不在返回列表时保留「当前值」选项，避免被静默覆盖；错误时仍可手填。
- 约定：Tauri v2 命令参数默认 JS camelCase ↔ Rust snake_case，前端一律 camelCase。
- 验证：`cargo check` + 3 个 llm 单测、`npm run typecheck`、eslint、`npm run build:web` 均通过。

## ci: 每次构建的产物自动发布到 Release

- 需求：GitHub Actions 每次执行生成的 artifacts 都自动发布到 Release。用户确认策略：
  按分支固定预发布（rolling，覆盖同名文件）+ 所有运行含 PR。
- `.github/workflows/build.yml`：把 `release-nightly` 换成 `release-continuous`，去掉
  main/master 分支限制；分支 push / workflow_dispatch → tag `continuous-<branch>`，
  PR → `continuous-pr-<n>`；`v*` tag 仍走原来的 `release` job 发正式版。
- 用 `overwrite_files: true` 覆盖同名安装包，下载链接长期不变；job 级 `concurrency`
  按分支/PR 串行发布，避免并发运行互相覆盖；fork PR 的 GITHUB_TOKEN 只读，跳过发布
  （Actions artifacts 仍照常上传）。
- 旧的 `nightly` Release 不再更新，可在 GitHub 页面手动删除。
- 验证：YAML 解析通过、`npm run typecheck` 通过。

## 调研：能否用 Rust GPUI 重写 UI 层（仅评估，未改代码）

- 结论：**技术上全部功能都能实现**，且本项目后端已是 Rust-first，迁移条件好于一般 Tauri 应用；
  但 5500 行前端 + 1871 行 CSS 零复用须重写，GPUI 仍 pre-1.0，当前不建议整体迁移。
- 分层判断：
  - 可原样复用：`src-tauri/src/{db,analyzer,monitors,config,logger,paths}/`（≈4000 行，纯逻辑 + 跨平台 crate）；
    仅需把 `runtime.rs` 里的 Tauri `AppHandle`/`Emitter` 抽象成事件总线，19 个 command 退化成直接函数调用。
  - 必须重写：全部 React 页面/组件/CSS、HashRouter、CSP、`navigator.clipboard` 兜底、Vite `define` 版本号注入。
  - 需换实现/外挂：托盘（NSStatusItem）、开机自启（LaunchAgent）、单实例、Dock 恢复、打包签名/自动更新、权限预检。
    官方 GPUI 不含这些；`gpui-ce` / `adabraka-gpui` / `fc-gpui` 等 fork 或 `tray-icon` crate 可补。
- 生态现状（2026-11）：crates.io 官方 `gpui` 停在 0.2.2，实际活跃的是 `gpui-pre` 0.3.x 周快照与
  `gpui-ce` / fork，API 常有 breaking change；`gpui-component`（longbridge，已更名 GPUI Kit）有 75+ 组件
  （DatePicker/Select/Progress/Chart/Table/Sidebar/Theme/Image/Markdown 等），覆盖本项目全部 UI 形态；
  GPUI 原生支持 IME 合成（中文输入）、剪贴板、`reveal_path`、文件对话框、系统暗色主题。
- 渐进路径：`tauri-plugin-gpui`（0.1.0，2026-10 发布，需 `tauri 2.12+` + `features=["unstable"]`）可让
  GPUI 窗口与 WebView 窗口在同一进程共存，适合逐页替换；缺点是两个不稳定栈叠加。
- 收益：去掉 WKWebView/WebView2 与 JS 桥、免 WebView2 依赖、内存/启动更轻；代价：整条 CI 打包/签名链路重建、
  Linux wgpu/X11/Wayland 门槛、组件库版本 pin 带来的维护成本。
