# 2026-11-03

## 每日分析定时支持「当天 / 前一天」配置

需求：定时分析的目标日期不再固定按 06:00 分界，改为可配置。

- 新增配置 `analysis.scheduleDateMode`（camelCase 前后端一致），取值
  `auto`（默认，沿用 06:00 前分析前一天）/ `today` / `previous`。
- `src-tauri/src/config.rs`：`AnalysisConfig` 加 `schedule_date_mode: String`，默认 `auto`。
  用 String 而不是 enum —— `Config` 加载失败会 `unwrap_or_default()` 整份重置，
  枚举遇到手改的非法值会让用户配置全丢。
- `src-tauri/src/analyzer/mod.rs`：
  - `scheduled_target_date(now, mode)` 增加模式分支，分界常量提到 `AUTO_PREVIOUS_DAY_HOUR`。
  - 新增 `normalize_hhmm`，Scheduler 比较时间前先规整（`9:00` → `09:00`），
    否则手输格式会让定时静默不触发。
  - 补 3 个单测：auto 分界/跨年、显式模式忽略时钟、时间规整。
- `Settings.tsx`：AI 分析卡片加「分析日期」下拉，hint 会实时预告
  「当前每天 23:00 分析当天/前一天的日报」；`effectiveScheduleMode` 复刻 Rust 的分界逻辑
  （前端常量 `AUTO_PREVIOUS_DAY_HOUR = 6`，改分界要两边同步）。

## 监控新增「全天监控」开关

需求：配置页必须填监控时间段，用户不知道全天该怎么配。

- 根因：`within_monitoring_window` 是**半开区间**（`now < end`），默认 `00:00-23:59`
  实际漏掉当天最后一分钟；且 UI 上没有任何「全天」选项。
- 新增 `monitoring.monitoringAllDay`（默认 `true`）。`apply_schedule` 里
  `in_range = all_day || within_monitoring_window(...)`，全天后完全不受时间段影响。
- **老配置迁移**：`ConfigStore::load` 用 `has_config_key(text, "/monitoring/monitoringAllDay")`
  判断字段是否缺失，缺失时用 `infer_all_day()` 按原起止时间推断（空 / 00:00-23:59 → 全天）。
  否则新字段默认 true 会把用户自定义的 09:00-18:00 静默改成全天。
- 前端：监控卡片顶部加 switch-row「全天监控」，开启时时间段输入 `disabled`；
  新增 `.input:disabled`、`.form-grid-after-switch` 两条样式。
- 测试：`config::tests`（推断 + 字段探测）、`monitors::tests`（半开区间 + 跨零点）。

## 全天/自定义时段互转（同日前一轮的补充）

反馈：时间段一旦选了值就删不掉，回不到全天。

- 根因：`input[type=time]` 在 macOS WKWebView 里没有清除按钮，清空后 `value || '00:00'`
  的兜底又把它显示成 00:00，等于永远出不去。
- 做法：**全天时不再渲染 time 输入框**，换成只读条
  （`time-window-static`：时钟图标 + `00:00 — 24:00` + 右侧「自定义时段」文字按钮）；
  自定义时段时在 hint 行提供「恢复全天」文字按钮（`.link-button` / `.field-hint-row`）。
  两个方向都有就近出口，顶部 switch 仍是主控，三者共用 `monitoringAllDay`。
- 视觉验证方式：手写 `/tmp/monitor-preview.html` 引真实 `globals.css`，
  用 Edge `--headless --screenshot` 截图 + `sips` 裁切放大检查，无需起 Tauri。
  注意 `< 900px` 时 `.form-grid` 变单列，验证宽屏要用 ≥1100 的窗口尺寸。

## 日报工具条：已分析胶囊随滚动条出现而整行换行

现象：选第一个已分析日期不换行，选第二个及以后就换行。

- 根因不是选中态，而是**页面从「不滚动」变「要滚动」**。`::-webkit-scrollbar{width:10px}`
  是自绘滚动条，会真占 10px 布局宽度：内容短时工具条可用 662px，出现滚动条后只剩 652px。
  1000px 默认窗口下：日历 145 + 分隔线 1 + 「已分析」36 + 间距 30 = 212，7 个胶囊 441px
  （合计 653px）刚好卡在中间，多的 10px 一没就整组掉到第二行。
- 修法（`globals.css`）：`html{scrollbar-gutter:stable}` 常驻预留槽位（宽度恒为 652）；
  `.pill-group` 改 `flex:1 1 0; min-width:0` —— flex 换行是按「基准尺寸」分行，
  只给 `flex-shrink` 仍会整组掉行，必须让 basis 为 0 才会留在本行内部换行；
  `.toolbar-divider/.toolbar-label` 加 `flex:none`；胶囊内边距 10→9px（7 个可排一行）。
- 结果：6~7 个胶囊恒为一行，8 个恒为 7+1 两行，且与滚动条无关。
- 复现/验证方法：把 `globals.css` 和 `<edge>` headless 的 `--dump-dom` 结合，
  在页面里打印 `toolbar.clientWidth` / 胶囊行数 / `innerWidth-clientWidth`；
  截图对比用 `--screenshot`。用例放 `/tmp/wb-toolbar-test/`（临时，不入库）。
  注意改 `<link>` 的 href 后再测量要等 `load` + `setTimeout`，否则量到的是无样式布局。
