# 2026-10-28

## Electron → Tauri 2 迁移（分支 feat/tauri）

- 需求：新拉分支把桌面框架从 Electron 换成 Tauri。分支 `feat/tauri`，两个提交：
  `c5dbc92`（迁移主体）、`2ab7ee1`（macOS Dock 恢复窗口）。
- 架构：`src-tauri/`（Rust，全部主进程能力）+ `src/renderer/`（React 不变）。
  前端 IPC 收敛到 `src/renderer/src/lib/api.ts`，挂到 `window.api`，
  页面只把 `window.electronAPI` 批量替换为 `window.api`。
- 关键依赖选型：tauri 2 / rusqlite(bundled) / xcap(截图) / active-win-pos-rs /
  user-idle / reqwest(OpenAI 兼容) / tauri-plugin-{single-instance,autostart,opener}。
  弃用：electron-vite、electron-builder、better-sqlite3、sql.js、active-win、openai SDK。
- 兼容策略：表结构、config.json 格式不变；`paths::resolve_data_dir` 会优先复用旧
  Electron 数据目录（`Desktop Monitor` / `desktop-monitor`），升级零迁移。
- 踩坑：`tauri.conf.json` 的自定义 CSP 必须包含 `connect-src ipc: http://ipc.localhost`，
  否则 WebView 内的 invoke 全部被拦，表现为「界面正常但数据不加载」。
- 验证方式（可复用）：临时往渲染层注入 `window.__TAURI_INTERNALS__.invoke('app_quit')`
  的脚本，配合 `HOME=<临时目录>` 启动 debug 二进制；进程在数秒内自行退出即说明
  「页面加载 + CSP + 命令注册 + 优雅退出」全链路 OK。注意 `cargo build` 出来的是 dev
  模式（加载 devUrl，需先起 `npx vite`），只有 `tauri build` 才走内嵌资源 `tauri://localhost`。
- 已知限制：Tauri 无 powerMonitor 等价物，锁屏改由空闲超时近似；便携版依赖 WebView2。
